# Приложение для парсинга вакансий с разных сайтов

## Общая архитектура

```
src/
├─ parsers/                # Парсеры конкретных сайтов
│   ├─ baseParser.ts       # Бэзовый абстрактный парсер
│   └─ ozon/               # ozon
├─ models/                 # Типы данных и DTO
│   ├─ vacancy.ts          # Vacancy, company и др.
│   └─ siteConfig.ts       # Конфиги парсеров
├─ services/               # Сервисы: сбор, кэширование, запись
│   ├─ parserService.ts    # Инъекция парсеров
│   └─ storageService.ts   # Сохранение в БД/файлы
├─ repositories/           # Репозитории для работы с данными
│   └─ vacancyRepository.ts
├─ utils/                  # Утилиты: очистка, нормализация
│   └─ normalize.ts
├─ config/                 # Конфигурация проекта
│   └─ index.ts
└─ main.ts                 # Точка входа
```

## Ключевые компоненты

1. **`src/entity.ts`** – общие типы (`company`, `Vacancy`) и интерфейс `SiteParser`.
2. **Парсеры** (`src/parsers/*`) – каждый парсер реализует метод `parse(url: string): Promise<Vacancy[]>` и использует Playwright/Puppeteer для извлечения DOM‑элементов.
3. **Модели** (`src/models/`) – содержат TypeScript‑типы и вспомогательные интерфейсы, чтобы гарантировать единую структуру данных независимо от источника.
4. **Сервисы** (`src/services/`) – orchestrating layer: 
   - `parserService` собирает данные через зарегистрированные парсеры.
   - `storageService` сохраняет результат в нужное хранилище.
5. **Репозитории** – абстракция доступа к хранилищу (БД, файл, API).
6. **Утилиты** – функции нормализации (удаление лишних пробелов, приведение к единому формату даты и т.д.).
7. **Конфигурация** – централизованные настройки (API‑ключи, таймауты, выбор парсеров).

## Поток работы

1. Пользователь Provides URL → `main.ts` определяет нужный парсер по домену.
2. `parserService` вызывает `parse()` конкретного парсера.
3. Полученные объекты `Vacancy` проходят через `utils.normalize`.
4. Нормализованные вакансии передаются в `storageService` для сохранения.
5. При необходимости выполняется повторный парсинг/обновление.

---

Эта структура обеспечивает:

- **Изоляцию** логики каждого сайта.
- **Единый контракт** (`SiteParser`) для всех парсеров.
- **Повторное использование** моделей и утилит.
- **Легкое расширяемость** – добавить новый сайт – лишь создать новый пак парсеров.
